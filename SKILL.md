# Publishing to the owner's site

The site is plain files: Markdown notes in `content/`, built to static HTML by `tools/build.py`, hosted on Cloudflare Pages, which rebuilds on every push to `main`. Skills that make the work (furniture CAD, metal casting, concrete molds, robotics) hand their outputs to this skill for the site part.

## HARD RULE: the quality gate (the owner, 26 Nov 2026)
Nothing goes on the site until `python3 tools/gate.py --changed --write` in the site repo passes for every page you touched, and the refreshed `tools/gate.lock.json` is in the same PR. This replaces "run the checks you think apply": the gate runs all of them, on every page you changed, and the site's build (which Cloudflare runs on every push to `main`) refuses to build while any page differs from its last pass, so the old deployment stays up. No PR merges without the gate's output pasted in it. CI not starting is not a reason to skip it: the gate is local.

What it fails (details in the site's `tools/gate.py`):
- **CAD fidelity** (`tools/gate/cad_fidelity.py`, every GLB): stand-in names, bare-box primitives and parts under the triangle floor on any real-world object (vehicle, tool, body, bought hardware), a vehicle under 150k triangles or with a boxy body, visible facets, floating parts, parts inside parts. Context objects count: a truck, a plane or a mannequin around the piece is held to the same bar as the piece.
- **Photo match** (`tools/gate/photo_match.py`): every real-world vehicle, tool or body needs reference photos from front, side and one more view in the site's `tools/gate.json`, and the shipped model, rendered from each photo's camera, must overlap its outline (IoU >= 0.90) and reproduce its interior detail (edge recall >= 0.55). A right outline with no grille, lamps or glazing fails.
- **Crop and aspect** (`tools/gate/page_check.mjs`): any cover crop that hides anything but plain white cyc, any stretched image, any image drawn wider than its file. No class or attribute skips it.
- **Theme**: `theme_audit.mjs` on the page.
- **Render quality**: renders on white, no render noise.
- **Blind critique** (`tools/gate/critique.py`): a different model, given only the page as a visitor sees it, 3D close-ups and the design-taste guide (never the maker's notes), scores it on the rubric. Every gate passes, no zero, at least 20/24.
An exception goes in the page's `allow` list in `tools/gate.json` with `why` and who confirmed it; never loosen a threshold to get a page through, never hand-edit the lock, never run the build with `AR_GATE_SELF`. Pages that were live before the gate are `legacy` in the lock with their known fails; the first change to one has to pass in full.

## Before you touch a page
1. Pull the latest `main` (other sessions edit the site the same day) and work on your own branch.
2. Read `references/site-structure.md` (how a note becomes a page) and `references/brand-on-the-web.md` (fonts, colours, spacing, what never goes on the site).
3. Changing an existing page: read the whole note first. Hand-built pages carry their own `<style>` block; find the rule you need and change it there.
4. Screenshot the page as it is now (`--prefix before-`), so you have something to compare against.

## Standing rule: on theme and up to date (the owner)
The whole site stays on the brand theme, and every project page matches the latest version of that project: renders, 3D previews, specs, drawings and animations. When a project gets a new version anywhere (CAD, renders, a GLB in the project's files), the site's page, its home and category cards, and its 3D tile move to it in the same session. Before any site PR, run `theme_audit.mjs` on the whole site (no FAILs), `scripts/version_check.py` (a page using an older file than the repo already holds, and STALE: a still, PDF or video whose version is older than the 3D model on the same page, e.g. a v6 render beside a v7c GLB) and `scripts/source_check.py --projects <project files>` (a page whose source files in the project changed after the page's last commit: renders, buy lists, guides, firmware notes). `version_check` alone can't see a project that moved on outside the repo. `source_check.py --write-lock` also compares every versioned file on the page (GLB, still, PDF, video) with the newest model version in the project files (each page's `versions` lines in `tools/sources.json`), so a new `_v7f.glb` dropped in the project files fails the page with no config change, and it writes `tools/versions.lock.json`. The site's build reads that lock and refuses to build a page that links an older file, so a stale page can't deploy. Commit the refreshed lock with every site PR. Exceptions go in the page's `allow` list with the reason and who confirmed it; a temporary one says so and names what it waits for. Every page built from project files has an entry in the repo's `tools/sources.json`; add one when you build a page, and when a project gets a new pass (an audit, a redesign), rebuild every part of its page from the new outputs, not just the images.

## One studio look (the owner, 26 Nov 2026)
Every image, video, 3D tile and drawing on the site follows the studio look guide (design-taste `references/studio-look.md`, the brand kit's LOOK.md): the four font cuts only, the one palette, the logo at its fixed size (54 px on the site, never scaled by eye), crop marks, lowercase mono tags on accent chips, and reels that end on the white site-card end card. Run its 10-line gate on any media before it goes on a page; media that fails stays off the site.

## Renames and redesigns reach every page (the owner, 25 Nov 2026)
A project's names live in its record, `RECORD.json` in the project's folder in the project files: the current name, URL, piece names, and what they used to be (`renamed`, `was`). Whoever renames a project or a piece, anywhere (a reel's labels, a sheet, a chat with the owner), updates the record in the same turn, and the site follows in the same session. The page's entry in `tools/sources.json` points at it with `"record"` and lists it under `sources`, with the latest reel and sheets, so a newer record or reel marks the page BEHIND. `scripts/name_check.py` (run by `source_check.py` on every publish) fails a page whose URL, name or piece names differ from the record, any old name or link to an old URL anywhere on the site, any card pointing at the page without the current name, and a missing old-URL redirect in `site.json`. `--write-lock` saves the names in `tools/versions.lock.json` and the site's build refuses retired names and old links, so a renamed project can't go live half-renamed. Rename the note and its URL with the project; media files may keep old names. A page in `sources.json` with no record gets a WARN: add one when you next touch the project.

## Making the change
- New project page: follow `references/adding-a-page.md` and start from `templates/project-page.md`.
- A piece with a model: render, 3D viewer and dimension drawing sit inline, side by side, with the spec table under them (`references/inline-layout.md`). Never put the viewer and its drawing in separate sections.
- No static angle or orthographic strips (view 1/2/3, front/side/top rows) of a piece that already has a turning 3D viewer on the page: the viewer shows every angle, so the strip is clutter. Stills next to a viewer earn their place only as variant buttons (seasons, stones) or a render of something the viewer can't show. `lint_page.py` errors on `-angleN`/`-viewN`/`-ortho` stills beside a viewer.
- Images, video and GLBs: size and compress them before committing (`references/media.md`). Full-size originals stay outside the repo.
- Someone else's image (a maker's product photo, a reference): their largest original, credited and linked in a mono caption under it.
- Show each project once per page: nothing in a grid that is already in the hero or a band above it.
- Project cards everywhere are the home page card: a 4:5 window on the cyc, the name in caps on the left and one fact in mono on the right (`.ar-cards` / `.ar-card`, or `%% portfolio %%`; see `references/inline-layout.md`). A project with a 3D model gets the model in its card, as on the home page.
- One header on every page, laid out as on the home page: work nav on the left, logo in the centre, studio nav on the right, a burger on phones. Nav buttons never move between pages. Every category in the nav links to its own page (`/sculpture`, `/robotics`), never to the home page or an anchor on it.
- Sculpture vs furniture: the owner's carved and cast pieces are sculpture even when they're usable (Studio Shrine Bench, Nine Lives sawhorses, the Moth case). The Furniture tab is only for Core Studio Furniture work. Ask before moving a piece between sections. On the home page, sculpture projects sit in the Sculpture group, never in a section of their own. Each home section shows every piece on its category page (in the section, or once in the hero or a band above it), in the category page's order; when you add, remove or reorder a piece on a category page, change the home section in the same PR. `lint_page.py` errors on any mismatch on every run.
- Retired: Wood Lenses (removed 2026-11-18 at the owner's request; `/wood-lenses` redirects to `/robotics`; backup in the project files and git history). Don't bring it back unless the owner asks.
- No outside artists' names or inspiration credits on public pages. Credit only the maker of a photo or product that appears on the page.
- Renders for the site run on cloud machines (this session, RenderBeamer, GarageFarm), never on the owner's Mac; the Mac is only for downloads and moving files. Animations and big jobs go to GarageFarm through the `render-farm` skill (github.com/alicanrowe/render-farm), which uploads and submits without anyone clicking renderBeamer.
- When a project moves to a new version, every still on its page is re-rendered from the new model or taken down the same day. An old render stays up only in a section that says it's history (iterations, prototypes). Removed features go with their renders and captions (the Moth tool box, the stainless sheets).
- Changed media gets a new URL. `tools/build.py` appends `?v=<content hash>` to every local image, GLB, video, PDF, font, CSS and JS link at build time, so a changed file can never be served from a browser or CDN cache. Never rely on overwriting a file under the same URL: link media from page HTML attributes (src, srcset, data-src, data-model, href, poster) so the build can hash it, and if a script builds a media URL itself, put a version in the file name. A new media type goes into `MEDIA` in build.py. Check with `grep -c '?v=' dist/<page>/index.html`.
- Every page is on the one site theme (shared light header, Newsreader 200/300, Plex Mono only for small numbers and dimensions, white page). There are no per-page custom themes: the Moth night band, script title and dark header were retired on 19 Nov 2026 at the owner's request. Don't add an exception to `theme_audit.mjs` ALLOW to get a page through.
- Only show finished work: final renders and site stills go up once the design is locked. A page about something unbuilt says so at the top.

## Check before the PR (make-and-check loop)
1. `python3 scripts/lint_page.py --site <repo> <page>`: no errors; read every warning on the page you touched.
2. `node scripts/shoot.mjs --site <repo> --out <dir> /<url>`: builds the site and screenshots the page at 1440 and 390 wide, and reports console errors, 404s, broken images, viewers that didn't load and sideways scroll on phone.
3. `node scripts/layout_check.mjs --site <repo> /<url>`: opens the page at 390, 768, 1024, 1280, 1440 (also at 2x), 1680 and 1920 wide. It flags anything that runs past the window edge or is cut off by its container, sideways scroll, and grid or flex rows whose items start more than 80 px apart (a viewer high and drawings far down beside it). No lines allowed.
4. Every 3D model with wood on the page: `python3 scripts/web_grain_check.py model.glb [--spec piece.cadcheck.json] --sheet grain.jpg` (it decodes and dequantizes site GLBs itself; `solid_wood.py` ships next to it). It also fails `curved`: a part whose surface twists, sweeps or bends along its grain under a flat 2D texture reads as one board bent into shape (Shrine bench plank, 25 Nov 2026); bake those with hardwood-furniture-cad `scripts/web_laminate.py` (wood evaluated in 3D, same boards as the renders) and the check re-verifies the bake (`bake`). It checks each part on its own (a mesh merged by material is split and every piece checked), grain along the part, end grain only on end faces, and every long-grain texture straight along U with no exemption for names like "flat" or "end". A furniture viewer GLB is built with the hardwood-furniture-cad skill's `scripts/web_glb.py`, never hand-textured, regrained or joined; compress it with `gltf-transform meshopt` (gltfpack merged its parts and dropped the names). Then `blender -b -P scripts/glb_zfight_check.py -- model.glb` (decoded): surfaces of two materials on top of each other, facing the same way, flicker as the viewer turns. `scripts/glb_zfight_fix.py` sinks partly covered vertices under the covering surface (face deletion only with --delete, which has torn thin parts). Any web GLB that was simplified, decimated or fixed must then pass `blender -b -P scripts/glb_fidelity_check.py -- full.glb web.glb`: every part compared with the full model, so crushed, shattered, torn or missing parts fail. Look at the model up close from two sides too.
5. Every 3D model on the page, wood or not, before it ships: `node scripts/flicker_render_check.mjs --site <repo> --page /<url>` and, for a model on the home page, `--home <model name>`. It renders the viewer the way the site does (model-viewer, or the home page's own three.js tiles), turns the camera 0.02 degrees a frame at 6 to 12 headings, near and far, and fails on any patch of pixels that flips back and forth. That is flicker however it is caused: coplanar faces, a screen or decal sitting on its body, double-sided panels back to back, transparent sorting, shadow acne. A static geometry check can pass a model that still flickers (the robot project v3 did). On a FAIL, open the red overlay it saves, then `node scripts/glb_coplanar_check.mjs full.glb` names the parts that touch; move them apart in the full model (see `references/check-loop.md` 3e) and check again. Do not ship a model with a FAIL.
6. `python3 scripts/check_image_backgrounds.py --changed <repo>`: every image the branch adds or changes sits on
   white (the owner's rule: white unless they ask otherwise). FAIL on black corners or a transparent PNG published
   as is. Flatten renders with its `on_white()`; a real photo that is dark on purpose goes in `--allow <name>`.
   theme_audit checks the page background, not the pictures on it, so this one is separate.
7. `node scripts/theme_audit.mjs --site <repo>`: every page on the site, checked against the brand theme in the browser. No FAIL lines (see `references/check-loop.md`).
8. Look at both screenshots against the brand, the page's neighbours on the site, and any reference the owner named. Write down everything that's off, fix it, shoot again. Repeat until nothing is on the list (`references/check-loop.md`).
9. Only screenshots that passed go to the owner.

## PR and deploy
Run `python3 tools/gate.py --changed --write` last, after every other change (any later edit changes the fingerprint and the build will refuse it). Open a PR from your branch with before/after screenshots at both widths, then follow `references/pr-and-deploy.md`. When the checks pass, merge it yourself without asking (the owner's standing rule since 18 Nov 2026). Merging to `main` publishes the site in about a minute. Then run `node scripts/theme_audit.mjs --site <repo> --live https://the owner's site /<url>`, which loads the published page cache-busted like a hard refresh. Check the live page at both widths, then send the owner the link. A page is done when the live audit passes, not when the branch does.

## Project registry
When you publish or update a project's page, update that project's row in the project registry (`PROJECTS.md` next to the eta-estimating live data): status, the live URL, and what's next. If the project has no row, add one. That way "where is X" questions find the page.

## Excuses that don't count
Each of these is a shortcut that ends in a broken result. If you catch yourself thinking the left column, do the right column.

| The excuse | What to do instead |
|---|---|
| "gltfpack defaults are fine for this GLB" | Engraved or boolean-cut plates have long sliver triangles that the default 14-bit positions crack into grey streaks and flicker. Pack those with `-vp 16`, then run `flicker_render_check.mjs --page`. |
| "It looks fine on desktop" | Shoot it at both widths and run layout_check at every width before the PR. |
| "The old render is close enough" | Run version_check and source_check; a stale file on the page fails. |
| "The reel/sheet has the new names, the page can catch up later" | Update the project's `RECORD.json` and the page in the same session; `name_check.py` fails the old name on every page, card and link. the jewelry line stayed on the site a day after the reel called it Imago (25 Nov 2026). |
| "A 4:5 cover grid makes the photos line up" | It crops the work. Galleries use justified rows with every photo whole (inline-layout.md, "Galleries"); `layout_check.mjs` fails `CROP` (/team, 25 Nov 2026). |
| "The gate is slow / CI is down, I'll merge and gate later" | The build refuses an ungated page; merging just breaks every deploy until someone runs it. Run `tools/gate.py --changed --write` before the PR. |
| "It's only context around the piece (the truck, the tools, the mannequin)" | Context is held to the piece's bar. Low-poly kei trucks went live on /kei-benches (26 Nov 2026) because only the bench was judged. Model the real thing from photos or leave it out. |
| "The outline matches the photo to 6 mm" | Outline is not fidelity. The truck matched its side photo and still had a 528-triangle cab and block mirrors. Photo match scores interior detail too, from at least three views. |
| "I scored it on the rubric myself" | The maker never grades its own work. The gate's blind critique scores it. |
| "I'll add an allow entry so it passes" | An allow entry needs the owner's say-so and a reason. A fail you disagree with goes to the owner, not into the allow list. |
| "Merged means it's live" | Run the live audit on the published page; it's done when that passes. |
| "While I'm in here I'll also tidy/refactor this other bit" | Change only what the task needs. Smallest diff that works; no new options, helpers or files nobody asked for. Note other ideas for later instead. |

## Keep this skill improving
When a site change goes wrong, or the owner corrects something on a page, write the lesson into the matching reference (and `references/lessons.md`, dated) in the same session, add a check to `scripts/lint_page.py` if a script could have caught it, then commit and push to this skill's repo. No private data: no emails, home paths, client names or unpublished prices.

**Words.** Page copy, project blurbs and captions in the client's name follow the `human-voice` skill (`../human-voice/`): build from the client's own words, invent nothing, and run its `voice_check.py` before the page goes live.

**Design taste.** How a page, render or piece looks is judged against the shared `design-taste` skill (`../design-taste/` next to this skill): read its principles and banned moves, and score visual work with its rubric before showing it. When the client critiques how anything looks, log the exact words in its `critique-log.md` in the same session, distil them into its principles or rubric, and publish it with `_publish/sync.sh design-taste`.
