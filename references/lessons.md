# Lessons from site work

Dated, newest first. Each lesson is also written into the reference it belongs to.

## 2026-11-22
- **The live audit passed a page that was not live yet.** Right after merging Cast Chairs, `theme_audit.mjs --live` reported `ok` for /cast-chairs while Cloudflare was still building and the URL returned 404: an error page has no off-brand text to fail. The audit now FAILs any page that answers with HTTP 400 or above (or not at all). Wait for the Cloudflare Pages check on `main` to finish before the live audit, and confirm the page content with a fetch.

## 2026-11-19
- **Moth is raw white ash until the final finish (the owner).** The web GLBs (v6w, v7c) carried a near-black ash texture, so the home hero and cards showed a black case while the text said raw white ash. `scripts/glb_recolor_texture.py` swaps a material's base-colour texture for a recoloured copy that keeps the grain. Check a model's colours against the page text before publishing it.

## 2026-11-19
- **"Outdated" pages that pass the audit.** the robot project and Info passed `theme_audit.mjs` (right fonts, inks, no plates) but still looked old next to Nine Rests: centred layout, grey tracked caps subtitles, boxed cards, a ruled stats band. The audit checks the brand tokens, not the layout, so the check loop now also compares every reworked page side by side with Nine Rests (brand-on-the-web.md, "The current page look"). Pages sharing a template are restyled once through a shared stylesheet loaded last (the site repo's `static/assets/lc-sheet.css`) rather than by patching each page's own overrides.

## 2026-11-18
- **Latest version everywhere (the owner's rule).** The Moth page moved to v6w (with the drawer stand) but the home hero still loaded v6s. `version_check.py` now flags any page using an older version of a file than its folder holds.
- **A bench can be sculpture.** Asked for "sculpture only" on the Sculpture page, I moved the Studio Shrine Bench to Furniture because it's a bench; the owner moved it straight back: carved pieces are sculpture even when usable. Don't sort by function; ask before moving a piece between sections.

The shared header now uses the home layout and both have the same phone burger. `theme_audit.mjs` records where each nav word sits (as a % of the width) and fails any page more than 1% off the home page, on desktop and phone. A 5% vs 6% logo position on phone came from 18px vs 23px side padding.
- **Cards matched across pages.** The AI, Robotics and Sculpture pages used 4:3 tiles with three caption lines; the owner asked for them to match home. All project lists now use the home card (inline-layout.md, Project cards), and `lint_page.py` errors on the old tile styles. A skill card with a 3D model (Concrete Mold Casting) shows one K pot cut from the K mold GLB: keep the `CAST*` nodes, drop the rest, and carry the meshopt-compressed buffer views over as they are.
- **Crop on the subject.** Mandelbulb tiles were centred on the image, not on the subject (Bulb's centre of the burst is 60% across). Use `object-position` worked out from the focal point (inline-layout.md).
- **Category nav goes to a category page.** Sculpture linked to the home page; the owner expected a Sculpture page. `lint_page.py` errors on a nav item linking to `/`.
- **Site-wide theme audit.** The owner asked whether the theme had reached every page; the skill only checked one page's source, so nobody could say. A crawl of all 22 pages found: the home page's own header (off-white bar, centred logo, split nav with different labels and a Commissions link) had drifted from the shared header on every other page, and the phone menu still used the old mauve; Dancers, the app guide and Moth use the drawing red `#96281c` for step numbers, labels and links; Dancers had a pink plate behind its safety note (fixed); parts cards and the skill pages' GitHub card are boxed. Added `scripts/theme_audit.mjs` (every page, computed styles, header consistency) and made it a step before every PR (check-loop.md 3b, brand-on-the-web.md).
- **Never repeat a project on a page (the owner's rule).** The home page Sculpture group listed Moth, Fawn Orchard and Nine Rests, which were already in the hero and the Nine Rests band above it. Each project appears once per page; `lint_page.py` now errors on it.
- **Screenshots of pages with looping video.** `networkidle` never fires while a video loops, so `shoot.mjs` timed out on /k-concrete-vessels. It now waits for `load` and gives network-idle 10 s at most.
- **Inline template, drawing labels.** First test of the project-page template: an 860-unit SVG shown 460 px wide turned 15-unit labels into 8 px text, and captions were left-aligned under centred media. Fixed by sizing labels for the shown width (inline-layout.md) and one square frame per column with centred captions (template).
- **Home page plumb line (GRAVITY / GRACE).** The home page is `layout: raw`: a full HTML document of its own, with no shared header, nav or footer added by the build, so nav or font changes in `site.css` don't reach it and have to be made there too. The plumb line swings on scroll or touch and only turns firebrick, with GRAVITY and GRACE, when it comes to rest: that is the only place the red appears. Motion changes need several screenshots or a recording to check, not one still. **Polish pass (PR #3):** the flat grey cone read as clip art; a small object drawn in SVG needs a material (brass body, steel tip via horizontal linear gradients), a few turned-ring hairlines, and where it attaches (knot, pin). Labels with a hard 3px light halo over a busy photo read as outlined and blurry; use the site's on-photo convention instead: white text with a soft dark edge (two blurred dark copies, tight about 1px plus wide about 5px) on photos, plain ink with no halo on the plain cyc, 13px minimum. Check the coloured state over the brightest part of the photo too: pale red on gold vanished until its edge went deep red. In headless Chromium with SwiftShader the pendulum takes over 30 s to settle, so wait or force `.on` to capture the rest state. A hidden (`display:none`) SVG still runs its rAF loop and wrote NaN every frame on phones; skip drawing when its box is 0.
- **MouthPad photo (PR #2).** Someone else's product photo: use their largest original (1632 x 805 from the maker's site), keep it unaltered, credit and link them in a mono caption under it, give the `<img>` its real width and height, cap it at 900 px on desktop and full column on phone, and check both widths before the PR. A white-background product shot sits straight on the page with no frame.
- **Moth: viewer and drawing inline.** The 3D viewer and the dimension drawing were in separate sections, so nobody read them together and a stale viewer went unnoticed. They now sit side by side with the spec table (inline-layout.md). The same page shows the cost of stacking overrides: `.ds-stand` ended up defined six times with `!important`. Change the rule in place (site-structure.md); `lint_page.py` warns when a selector is defined three or more times.
- **Mandelbulbs: matching a fractal preset to its originals (Syd, 19 Nov 2026).** The first Syd pass stood the camera inside the box city and shipped crunchy, cluttered blocks that looked nothing like the renders. What made it read right: find what the originals are physically doing (Syd is an ultra-wide lens, 145°, hugging the outer face of the scale-3 box, so slabs stretch to a vanishing point over black void), then smooth the surface (reflection off, step 0.5, one colour band per form via `colF` 1). Judge at the real canvas size: the engine's surface epsilon scales with pixel size, so a 700 px test render showed a horizon and void that moved at 1240 px; check desktop (1440 at 1.6x) and phone before settling. Sample the palette from the original with k-means instead of guessing. The kit's score is a guide only: the old bad preset already beat the leave-one-out ceiling.
- 2026-11-19: merging GLBs with trimesh drops material extensions (KHR_materials_transmission, ior, emissive_strength). Clear acrylic then renders opaque white over anything behind it, and screens lose their glow. Copy the `extensions` block back onto each material by name from the source GLBs before compressing, and add the extension names to `extensionsUsed`.
- 2026-11-19: trimesh also writes every texture as PNG and can point two images at one buffer view. If a repack re-encodes that view as JPEG, update the mimeType on every image that shares it, or gltf-transform's texture step fails with "width 0".
- 2026-11-19: `glb_flicker_check.mjs` uses the UV u-value as "colour" and a bounding-box overlap, so a flat textured face (a silkscreened plate, a logo) split into triangles shows hundreds of false hits. Confirm a hit by intersecting the actual coplanar triangles (shapely union area against the sum of areas) before changing the model.
- **2026-11-19 Dancers page stale after a build audit.** All 24 machines were re-rendered and re-audited after the page's last build, but `version_check.py` only compares files inside the repo, so it passed. The page kept old renders, prices, guides and a Drag Queen solenoid diagram of a design that no longer existed; the page builder also refreshed images and buy lists but never the guides, recipes or how-it-works text, and closed one section early. Added `scripts/source_check.py` and the repo's `tools/sources.json` (page to project-file globs); it flags any source newer than the page's last commit. When rebuilding a section, regenerate every block from its source and check the HTML nests (one `<section>` open per close).

## 2026-11-19: Moth 3D grain ran diagonally and across the parts
The Moth source GLB has no UVs (its grain was procedural). The web "lite" GLB got a baked ash texture on auto-projected UVs, so 59 of 79 parts showed grain diagonally or across the part, and the legs looked wavy. No check looked at UVs: the render grain audit lives in the furniture skill and only covers Blender renders, and the site checks only looked at colour and version. Fixed with `glb_regrain.py`, which projects each face with U along the part's long axis. `glb_grain_check.py` now runs on every wood GLB before the PR. It also found 3 cross-grain parts on the walnut case tile.

## 2026-11-19: Nine Rests carved images showed stale for hours
The new images replaced old files under the same names, and browsers kept the cached copies (up to 4 hours). Only site.css and site.js were cache-busted. build.py now content-hashes every local media URL (`?v=<hash>`), so a changed file always gets a new URL.
- **2026-11-19 Wavy grain passed, the site lagged the model, the instruments flickered.** The grain check passed because the UVs ran along each part, but the texture itself was flat-sawn (cathedral figure), so every part still looked wavy. `glb_texture_check.py` now measures the grain direction in the texture (structure tensor) and fails flat-sawn figure. The site kept v7c while v7e sat in the project files, because the version checks only compared files inside the site; `source_check.py` now compares every versioned file with the newest model in the project files, and the site build refuses stale files from `tools/versions.lock.json`. The new check also caught a v7c build book that still said "cast brass, aged dark", and a shrine bench a version behind. Tool handles flickered where leather, thread, steel and silver layers sat on the same surface; `glb_zfight_check.py` finds them and `glb_zfight_fix.py` removes the covered faces (121 clashing pairs down to 14 on the Moth).
- **2026-11-19 Simplified tools shattered.** A lite GLB decimated uniformly left black wedge shards across thin iron stands and spirals. They didn't show at the default camera distance, only up close. Don't trust any simplifier on thin parts: `gltfpack -sa` (aggressive) dropped whole parts (a 108 mm spreader blade, the grip threads) while looking clean from a distance. Use plain `gltfpack -si` without -sa, or no simplify plus meshopt (`-c`), and prove it with `glb_fidelity_check.py`. Screenshot every viewer close up (about a third of the default distance) from two sides before shipping. Blender's decimate modifier and `gltf-transform simplify` both did worse here.
- **2026-11-19 Crushed and torn tools shipped twice.** The Moth instruments passed every check: grain, texture, z-fight, version. None of them compare the web model with the full model, so tools crushed by a lite simplify, parts dropped by `gltfpack -sa`, and a saw blade and chisel torn by the z-fight fix's face deletion all went live. The freshness check only compares version tokens, so it can't see damaged geometry under a current name. Added `glb_fidelity_check.py`: it samples every part of the full model and of the web model and fails any part whose surfaces disagree by more than 1% of its size, or that is missing. `glb_zfight_fix.py` no longer deletes faces unless given `--delete`. Run the fidelity check on every web GLB that was simplified, decimated or fixed.

## 20 Nov 2026: a model-wide z-fight tolerance crushed small parts
`glb_zfight_fix.py` sank vertices by 3x a tolerance taken from the whole model (0.4 mm on the 2 m Moth case), so 20 mm tools inside it moved over 1 mm and failed the fidelity check. Each mesh now uses at most 0.2% of its own size, and `--skip REGEX` leaves named parts alone. Compress web GLBs with `gltfpack -c -kn -km -ke -vtf` (no -si, no -sa); regrained UVs tile far past 0..1, so integer UV quantization breaks them without -vtf. `version_check.py` now reads the allow lists in the site's tools/sources.json, so an exception is written once.
- **Home sections mirror their category pages (2026-11-20, the owner: "the skill should have caught this").** the jewelry line was on the Sculpture page but missing from the home page's Sculpture row, and nothing compared the two. `lint_page.py` now checks, on every run, that each home section (`<div class="sec">` linking a category page) shows every piece on that page (in the section, the hero or a band) and in the same order, and errors otherwise. Reorder or add a piece on a category page and on home in the same change.
- **Variant stills switch the viewer (2026-11-20, the owner asked for it on the jewelry line).** The season renders beside each viewer looked like buttons but did nothing. They are now `[data-pick]` buttons; `viewer.js` used to press only the clicked control, so a second control set for the same viewer fell out of step. It now presses every control with the same `data-src`. Pattern in `inline-layout.md`.
- **Nine Rests is now Nine Lives (2026-11-20, the owner).** The sawhorse set was renamed: page `/nine-lives`, images in `img/nine-lives/`, piece codes NL-01..09, with 301s from `/nine-rests` and `/img/nine-rests/*` in `site.json`. Older entries here keep the old name as history. A rename moves the note, the image folder and every card and link in one PR, and adds redirects for the old page and media paths.
- **Fractal engine presets are rendered headless before they ship (2026-11-20, the owner: "syd still sucks").** The syd preset had been tuned by eye in one pass and never compared against the style the owner meant. To iterate on a preset, load `static/assets/fractal.js` in a small harness page in Playwright Chromium with `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`, set `data-manual` on `#fe`, and call `FractalEngine.Engine.draw` with Halton jitter for N samples (blend weight 1/(n+1)), then save `canvas.toDataURL()`. A 940×400 frame at 2 samples takes about 2 s, so a grid of 4 to 6 variants per round is cheap; render the final at 2350×1000 with 20 samples (about 2 minutes). Before shipping, render every other preset before and after the change and `cmp` the PNGs: they must match pixel for pixel. Preset-only features go behind optional preset fields and are emitted into the shader only when present, so the other presets' shaders don't change. In a floor reflection, give each sample one tilt for the whole frame (from the sample seed), not a per-pixel random one: per-pixel jitter leaves grain that 20 samples don't average out. Pass the primary ray's distance into the reflected march so the hit size matches the pixel; doubling it fattened small objects into discs.

## 21 Nov 2026: a 64-piece jewelry collection page
- **Drawings for many pieces at once.** Sixty-four hand-drawn dimension drawings were not realistic, so each motif gets one inline SVG with its four pieces' front views at one scale, traced from the same web GLBs the viewer loads (`scripts/glb_silhouette.py`): decode with gltf-transform, rasterise the triangles at 0.04 mm, trace outlines, draw width and height in the drawing red. Flat pieces (earrings, pendants, clips) lie in the GLB's XZ plane, so draw x against -z for them; rings and cuffs read best in XY. For an earring pair draw one earring.
- **Leave room for the dimension label.** On phones the height label of the widest piece ran past the viewBox edge. Keep the drawing area about 190 of every 300 units so the label fits beside it.
- **GPU instancing in optimised GLBs.** `gltf-transform optimize` turns identical stones into `EXT_mesh_gpu_instancing`. model-viewer draws them correctly, but trimesh places the shared mesh wrongly (a 2 m stone), which blew up the raster to gigabytes and got the build killed. The silhouette script now keeps only stones inside the metal's box. Check any GLB tool that reads optimised files for instancing support.
- **Variant stills from 4-view squares.** The casting skill's Instagram squares carry a hero plus three small angle views. As viewer buttons, crop to the hero (top 1080 x 750) so the page shows no angle strip beside the viewer.

## 21 Nov 2026: publishing a 53-file batch to a 64-model page
- **Flicker check on a big page.** `flicker_render_check.mjs --page` renders every model on the page, about 10 minutes each on a 4-core cloud machine, so a 64-model page takes hours. When only some models changed, pass the changed GLBs directly (`--orbit` set to the page's `data-orbit`) and split them across 4 parallel runs: 26 models took about 15 minutes, all passing.
- **Running the checks outside the repo.** The scripts load `playwright` and `pngjs` relative to the script, so copy them to a scratch folder that has `node_modules` (pngjs installed, playwright linked from the global install) and run them from there. Install `requirements.txt` first or the build fails on `import markdown`.
- **Handoffs through a full project folder.** When the project folder is near its limit, a write can look saved and be dropped. Count the handoff files against its file list before staging, and ask the maker to rewrite what is missing.

## 22 Nov 2026: a laminated sheet-metal piece (stacked plates) in the viewer
- **Blender exports every material double-sided by default.** A model built from stacked or butted plates has faces
  back to back at every joint; double-sided, they flicker as the viewer turns (flicker_render_check FAIL, thin
  horizontal streaks along the joints). Set `material.use_backface_culling = True` before `export_scene.gltf` so the
  GLB materials are single-sided, then check again.
- **Blender camera clip.** A camera made with `bpy.data.cameras.new` in a millimetre scene clips at 1000 units; pull
  it back past that and the render comes out empty (only the shadow catcher). Set `clip_end` when the scene is in mm.
- **Dimension red is `#96281c`** (22 Nov 2026). A drawing in another dark red (`#8b1d1d`) fails theme_audit on every
  label; generate drawings with the brand red from the start.
- **Small metal pieces in the viewer read darker than in Cycles.** model-viewer's neutral light makes a 0.5 grey
  metallic base look like gunmetal next to the render; lift the web GLB's base colour (about 0.68) to match the still.
- **Square hero from a 16:9 render.** Crop inside the frame (a crop box past the edge adds a black row that the
  background check may miss at the bottom); render wide at 2560x1440 and crop 1440 square for a sharp trio frame.

- 2026-11-22: the owner's site answers a bare page path with a 308 to the trailing-slash URL, so `curl -s` returns an empty body. Wait for a deploy with `curl -sL` (or `theme_audit.mjs --live`), never a plain curl grep.

Separately: `source_check.py --write-lock` drops the lock lines for any page whose project files aren't present on this machine; restore those lines from `main` before committing the lock, or the build refuses the other pages.

- 2026-11-23: The studio accent moved from firebrick to IKIYA lining green `#1D847E` (owner's pick). Card facts became green chips site-wide through `site.css`, so no page note changed. theme_audit had to learn the one allowed plate (white on the accent); otherwise every chip FAILs as "text on a coloured plate".

For a pinned stage (a scroll-scrubbed image sequence, say) make the stage `position: absolute` inside a tall section and set `transform: translateY(...)` from the section's `getBoundingClientRect()` on scroll.   page's URL, put each piece under its own variant heading with an id (`#hanging`, `#standing`), keep each variant's
  own trio, spec and details, add a 301 for the old URL in `site.json` redirects, merge the two `tools/sources.json`

  `lint_page.py` fails a home page that shows the same URL twice, so drop the other category's card instead of

- **2026-11-23 Clear acrylic in Cycles and on the web.** Laminated clear plates rendered near-black: a clear face lying on another face (clear on clear, or clear on metal) traps Cycles rays. Fuse all clear parts into one solid and pull it 0.02 mm clear of every opaque part for renders (0.15 mm for the web GLB, so nothing z-fights). Bare metal on a plain white world reads as white plastic: give the world a dark band above the horizon and a grey floor (the camera never sees it on transparent film). For the web, patch `KHR_materials_transmission` + `KHR_materials_ior` + `KHR_materials_volume` into the GLB JSON before gltfpack (it keeps them); model-viewer and three.js both render it.

## 2026-11-23: the PM case preview's grain broke again (the owner: "how did this grain get fucked again")
The Hardwood Furniture CAD card on /ai showed swirly contour-map figure on the panels and diagonal grain on the legs and rails.
